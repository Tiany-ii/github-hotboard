- 根因二：.dside-in 上的 max-height:calc(100vh - 80px) + overflow-y:auto，在某些 WebView2 下把侧栏裁成 0 高，整列空白
- 表格改回 display:table + width:100%，单元格加 overflow-wrap:anywhere 与 word-break:break-word，按容器宽度自然折行
- 侧栏去掉 max-height / overflow，只保留内层 sticky（.dside-in）
- 实测 1535 / 1080 / 820：抽屉、表格、页面的 scrollWidth 全部等于 clientWidth；200 字符的超长 URL 也不撑破

#35 [2026-10-27 21:08] v1.2.3 修复 HTML 表格不闭合导致整页错位（真正的根因）
- 根因：Markdown 渲染器遇到以 < 开头的 HTML 块时，读到第一个空行就收尾；而这份 README 的 <table> 每个单元格之间都有空行，</table> 从没被读到
- 后果：浏览器把后面整篇文档都塞进最后一个 <td>，表格被撑到 1576px，右列被挤空，看起来像「内容超出容器」
- 修法：HTML 表格单独处理，一直读到 </table>，再用 DOMParser 展开行与单元格，格内跑 inlineMd 保留链接
- 实测 1521 / 1280 / 1080 / 820：表格宽 1086 / 866 / 704 / 758，全部小于容器；抽屉与页面的 scrollWidth 均等于 clientWidth
- 附带修复：目录（TOC）恢复正常。之前文档被吞进表格，TOC 只能扫到零星几条

#36 [2026-10-27 22:08] v1.2.4 启动时按屏幕大小居中显示窗口
- 根因：create_window 写死 1480x950，比本机可用区域 1536x928 还高，Windows 只能把窗口挤到右下角并裁掉底部
- 新增 work_area()：用 SystemParametersInfoW(SPI_GETWORKAREA) 取主屏可用区域（已排除任务栏），与建窗同一坐标空间，不做 DPI 换算
- 新增 window_geometry()：按可用区域的 90% 取尺寸（上限仍是 1480x950，下限 1000x640），再算居中坐标
- min_size 跟着窗口一起缩，避免小屏上最小尺寸本身就把窗口撑出屏幕
- 新增 --geometry 参数，无界面打印可用区域与算出的窗口几何，方便排查
- 实测：本机可用区域 1536x928 → 窗口 1382x835 at (77,46)；启动后 GetWindowRect 实测值与计算值完全一致
