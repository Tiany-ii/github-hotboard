GitHub 热榜 · 桌面版

使用说明与注意事项 v1.0.0 · 2026-10-27 · 适用于 GitHub Hotboard.exe 与网页版

这是一个查看 GitHub 热门项目的本地看板：全站热榜、新项目榜、分类精选、DeepSeek 插件榜、我的榜单， 支持自动刷新、Star 增长曲线、自定义关注列表，以及详情页的双语 README 与 AI 总结。 数据直接来自 GitHub 官方接口，不需要注册、不需要登录。

一、怎么启动

方式 A：双击 exe（推荐）

  1. 双击 GitHub Hotboard.exe。
  2. 第一次启动会稍慢（约 15~30 秒：程序要解压自身、创建浏览器内核配置），之后一般 5~10 秒。
  3. 如果窗口出来了但内容空白，先等 20 秒——首次创建配置时加载确实慢。
  4. 窗口打开后会自动拉取数据，首屏大约 2~3 秒出现榜单。

方式 B：网页版（备用）

如果 exe 因为杀毒软件或系统原因打不开，可以直接双击 github-hot.html， 用 Edge / Chrome 打开，功能完全一样。也可以双击 打开热榜.bat，它会用无地址栏的应用窗口打开。

建议：把 GitHub Hotboard.exe 发送到桌面快捷方式（右键 → 发送到 → 桌面快捷方式），以后一键打开。

详情页：点任意一行进入

点榜单里的任意一行（项目名以外的位置），会整页打开该项目的详情：

  • 项目简介：原文在上、中文译文在下，一一对应。
  • 六项指标：Star、Fork、Issue、日均新增、创建天数、主要语言。
  • README 全文：自动解析标题、列表、代码块、表格、图片，徽章和纯装饰行会被过滤掉。
  • 两条曲线并列：左边是本机采样（从你使用起累积），右边是 star-history.com 的真实历史曲线，新装也能立刻看到长期趋势。
  • 右侧栏：目录导航（长 README 快速跳转）、项目信息、标签，以及同类项目推荐（按语言和标签匹配，点一下直接跳过去）。
  • 左上角「← 返回榜单」回到原来的位置，按 Esc 也可以。

中文翻译怎么用

顶部有三个切换按钮：仅中文 / 双语对照 / 仅原文。对照模式下，每一段原文下面紧跟它的译文，代码块、图片、表格不参与翻译，格式不会被破坏。

翻译有两种引擎，在「关于」页切换：

引擎要不要 Key能翻多少适合
DeepSeek要README 全文，质量最好经常看、想完整对照
免费在线翻译不要每天约 5,000 字符，够翻简介和开头十几段偶尔看看、不想配置

翻译是手动触发的：打开详情页不会自动翻译、不消耗任何额度。每个项目的详情页右上角都有自己的「翻译为中文」按钮，点它才调接口。翻过一次就缓存在本机，再看不再扣费。

随时可以暂停：翻译过程中按钮会变成「暂停 45%」，点一下就停。已翻好的部分立刻生效并保存，按钮随后变成「继续翻译（剩 N 段）」，想接着翻再点一次就行——不会重复翻已经翻过的段落，也不会重复扣费。

换引擎后能接着翻：之前用免费引擎翻了一半、额度用完了，这时填入 DeepSeek Key，再打开同一个项目，已经翻好的段落会原样保留，按钮显示「继续翻译（剩 N 段）」，点一下只用 DeepSeek 补翻剩下的部分。程序不会自动开始——需要你点一下，避免在你不知情时产生费用。想整篇都用 DeepSeek 重翻，点工具栏的「全部重翻」。

注意两点：① 如果你在「关于」页把引擎固定成了「只用免费在线翻译」，填了 Key 也不会生效，要切回「自动」；② 如果项目作者之后改了 README，旧译文会因为内容对不上而自动失效，需要重新翻。

额度用完会明确告诉你：免费引擎由 MyMemory 按 IP 计算额度（每天约 5,000 字符，实际比这个更紧）。一旦用完，页面会直接弹出黄色提示条，写明「为什么停」「什么时候恢复」「现在还能怎么办」，并把翻译按钮改成「免费额度已用完」，不会让你点了没反应、自己猜原因。

引擎默认是「自动」：填了 Key 就用 DeepSeek，没填就走免费接口。按钮旁边会显示当前引擎和免费额度还剩多少字。

API Key 可以存多个、随时切换

「关于」页的 Key 区域现在是一个列表：

  • 粘贴 Key、可选填一个备注名（比如「主力」「公司账号」），点保存就进列表并自动切换过去。
  • 下拉框切换 Key，立即生效，不用重开程序；已经打开的详情页下次点翻译就用新 Key。
  • 右侧「删除」只删当前选中的那个，删完自动切到列表里的下一个。
  • 最多存 8 个。列表和当前选择都存在本机，关掉再打开还在。
  • Key 只显示后四位（sk-…1111），不会明文展示在界面上。
导出的备份里不含 Key（也不含 GitHub Token）。这是刻意的：备份文件可能被拷来拷去，密钥不该跟着走。换设备后重新粘贴一次即可。
完全不想联网翻译也可以：精选的 65 个项目自带中文简介，离线就能看到中文。

AI 总结：判断这个项目值不值得看

详情页右上角的「AI 总结」会读一遍 README，再结合 Star、Fork、未关闭 Issue、创建时间、最近推送、许可证，给出一张决策卡：

小节回答什么
一句话定位它到底是什么
解决什么问题为什么存在、替代了什么麻烦
核心能力3~5 条，扫一眼就知道能干什么
上手成本要不要装环境、有没有 Docker、有没有在线 Demo
值得注意维护活跃度、许可证、明显短板
阅读建议想最快跑起来，该看 README 的哪一节

需要 DeepSeek Key（免费引擎做不了总结）。手动触发、不会自动跑，结果缓存在本机，同一个项目不会重复花钱；README 改了才会失效。一次约 2~3k token，不到一分钱。

它比「自己读 README」多出来的价值，在于把 README 里没有的信息也纳入了判断——比如「最近一次提交在 8 个月前，同时积压了 1,200 个未关闭 issue，维护可能停滞」。这类结论只看 README 是得不出来的。

两点说明：① AI 会出错，卡片底部标注了「以原文为准」，重要结论请回原文核对；② 如果某个项目的 README 只有徽章和图片、几乎没有正文，程序会直接跳过并说明原因，不会让模型硬编。

用哪个模型：默认 flash，可切 pro

「关于」页有一项「AI 总结模型」，两个选项：

模型适合什么价格（输入未命中 / 输出，元每百万 token）
deepseek-flash
V4.1-Flash		 默认。总结、批量总结、每日点评都够用 1 / 4（空闲）
2 / 8（高峰）
deepseek-v4-pro
V4-Pro		 想让它判断更细、少说套话时 4.5 / 13.5（空闲）
9 / 27（高峰）

下面还有一个「总结时开启思考模式」：勾上之后模型先推理再作答，结论更稳，但更慢更贵。默认关闭。切换后立即生效，设置存在本机。

翻译不受这两个设置影响：翻译固定用 deepseek-flash 并关闭思考。逐段翻译是机械任务，开思考只会变慢变贵，质量差异肉眼看不出来。

模型名会变。DeepSeek 已在 2026 年 7 月 24 日停用 deepseek-chat 与 deepseek-reasoner 两个旧名字。如果哪天接口报「模型名被拒」，到「关于」页换一个即可——程序会给出明确提示，不会只丢一个状态码。

AI 记录：译文与总结都在这里

「AI 记录」页分两块：上半是译文（段数、字符数、引擎、时间），下半是AI 总结（一句话定位、生成时间、类型）。顶部五张卡显示：已翻译项目、未翻完、已生成总结、占用空间、今日免费额度用量。

总结分两种，在表里用标签区分：详细是详情页生成的完整决策卡，一句话是「我的榜单」批量生成的定位句。同一个项目两者都有时只显示详细的那条。

  • 「进度」列显示已翻段数 / 可翻总段数，翻了一半的会标上「未完成」，顶部也会统计有几个。
  • 点项目名直接打开它的详情页，接着点「继续翻译」即可续翻。
  • 点每行右侧的 × 只删掉这个项目的译文，不影响别的。
  • 「清空全部译文」会一次性清空，下次查看需要重新翻译（会弹确认框）。
关于翻译成本：默认不自动翻译，只有你点了按钮才会计费。DeepSeek 按 README 长度收费，普通项目一次约几分钱；免费引擎不要钱，但每天只有约 5,000 字符额度，翻长 README 会中途停下并告诉你翻了多少段。两者都会缓存，同一个项目不会重复消耗。
一个限制：有些项目的 README 是用 HTML 写的（比如 sindresorhus/awesome），这类内容会原样显示、不做翻译，以免破坏排版。这类项目的简介仍然有双语对照。

几个操作要点

  • 点任意一行（项目名以外的地方）会从右侧滑出详情面板，看 Star 增长曲线和统计。
  • 点项目名会直接在浏览器打开 GitHub 页面。
  • 详情面板里可以一键「加入我的榜单 / 移出」。
  • 「我的榜单」支持一次粘贴多个：ollama/ollama, torvalds/linux 或每行一个，也能直接粘贴 GitHub 链接。
  • 批量总结：点「批量总结」，AI 会给每个关注项目写一句中文定位并标上类别，直接显示在项目名下面。一次调用搞定全部，比逐个点详情页便宜得多；已经有详细总结的项目会自动跳过。需要 DeepSeek Key。

连通性指示

顶栏「刷新」按钮左边有一个小药丸：一个圆点加一个数字，比如 ● 92ms。它每分钟自动探测一次 GitHub，点一下可立刻检测。

进入项目详情后，详情页顶栏最右侧会出现同一个状态（紧凑样式）——因为详情页是全屏的，会盖住主顶栏。两处显示始终一致，点哪个都能触发检测。

显示含义该怎么办
● 92ms连通正常（400 毫秒以内）不用管
● 860ms能连上，但延迟偏高刷新会变慢，可以调大刷新间隔
● 断开连不上 GitHub（断网、DNS、超时）鼠标悬停看具体原因，点一下重试

探测用的是 rate_limit 接口，不消耗 API 配额，所以放心挂着。鼠标悬停能看到「延迟多少毫秒、多久之前检测的」，点一下会用气泡提示当前结果。

状态变化时会怎样

场景药丸表现额外提示
一直正常绿色圆点，数字随每次检测更新无
变慢（>400ms）圆点变黄，数字变成新的延迟无（避免打扰）
从正常变成断开圆点变红、文字变「断开」，并外圈闪两下气泡提示「GitHub 连接已断开：原因」
从断开恢复圆点变绿、文字变回延迟数字，同样闪两下气泡提示「GitHub 连接已恢复 · N ms」
手动点击检测检测期间圆点变灰闪烁直接气泡给出本次结果（不重复提示）

断开期间刷新失败时，页面会继续显示上一次的缓存数据，药丸保持红色，鼠标悬停能看到具体原因（断网 / DNS / 超时）。

一键下载

详情页右上角的「下载」可以把项目拿到本地，不用再跳 GitHub 找 zip：

  1. 选下载内容：项目如果有 Release，会列出作者编译好的安装包（.exe / .zip 等）和「源码 ZIP」。每个选项下面都写了区别——安装包是能直接用的，源码是原始代码、需要自己装环境。
  2. 选保存位置：点弹窗右下角的「选择位置并下载」后才会弹文件夹选择框——打开软件或进入项目页时不会弹任何东西。选好后开始下载，显示进度、速度，可随时取消。
  3. 自动处理：源码 ZIP 会解压成 owner__repo 文件夹；安装包原样保存。同名目录已存在会自动加 -2，不会覆盖。

完成后点「打开文件夹」直接跳过去。程序只负责下载和保存，不会自动运行任何东西。

两点说明：① 网页版（浏览器直接打开 HTML）不支持选目录，会自动降级成浏览器下载；② 不支持断点续传，中断后需要重新下。

DeepSeek 插件榜

  • 点任意一行进入插件详情，和全站热榜一致：项目简介、指标、README、增长曲线都在。点项目名则直接打开 GitHub 页面。
  • 第一次点开某个插件时会读取它的仓库信息（一次接口调用），之后再看就是本地缓存。
  • 列表每次显示 200 个，底部有「再显示 200 个」；搜索和分类筛选覆盖全部 6,896 个，不只是前 200 个。
  • 加载速度：目录文件 8.7 MB，只有第一次需要下载。之后走本地缓存（约 1.1 MB）直接出图，同时在后台检查更新；6 小时内不会重复请求。

关注项目的变动提醒

每次打开「我的榜单」，程序会把这次拿到的数据和上一次比一遍，在表格上方生成一张变动卡。每条只显示真正值得看的变化：

标签含义
有新提交项目的 pushed_at 变了，说明作者推了新代码
★ +N / -NStar 涨跌（对比基线）
issue +N未关闭 issue 变化超过 3 个才显示，避免个位数抖动刷屏
N 天未更新超过 90 天没有提交，提醒你它可能已经停更

「我的榜单」标签上会出现一个红点，表示有新变动还没看过；点进该页红点就消失，但卡片会保留。

第一天用只会记录基线，第二天开始才有对比。所有数据都来自本机快照，不额外调用任何接口——用的就是打开「我的榜单」时本来就要拉的那一次。

每日简报

「每日简报」把当天散落的信息合成一页，随时打开都能看；每天第一次刷新时自动换新，不需要手动生成。

板块内容
一句话概述今天 Top 100 新进几个、掉出几个、关注的项目有几个变动
关注项目的变动和「我的榜单」顶部那张卡同源，没打开过我的榜单时显示上次的数据并标注
榜单异动新进榜 / 掉出榜，对比的是昨天最后一次的 Top 100 名单
今日涨幅 Top 5对比今天第一次刷新时的 Star 数，不是「最近几分钟」的增量
新面孔与黑马近 90 天创建且已进 Top 100 的项目；以及日均增速前三

配了 DeepSeek Key 的话，右上角「AI 点评今日」会用 2~3 句话概括今天的看点。一天只生成一次并缓存，重开不会重复花钱；点「重新点评」才会重算。

第一天打开会看到「第一次记录」：新进榜和涨幅都需要有昨天的基线，第二天起才有内容。新面孔与黑马不受影响，当天就能看。

三、增长曲线是怎么来的（重要）

GitHub 官方不提供历史 Star 数据接口。任何号称能直接画出历史曲线的工具，要么自己长期在采集，要么用的是第三方估算数据。

这个程序的做法是：每次刷新时，把当前 Star 记一个采样点，存在你自己的电脑上。所以：

  • 曲线从你第一次打开程序起开始累积，之前的历史补不回来。
  • 刚打开时显示「曲线正在采集」，属于正常现象。把刷新间隔调到 30 秒，几分钟后就有走势了。
  • 用得越久越完整。最多保留 150 个点，越近越密、久远的自动稀释。
  • 程序关掉期间不采样，所以曲线会有断档，这是正常的。
想看「日均增速」但不想等？新项目榜里的「日均」是用 Star ÷ 创建天数 算的， 不依赖本地历史，打开就能看，衡量的是项目自创建以来的平均吸星速度。

四、注意事项

⓪ 强制结束进程不会丢数据，但可能让下次启动变慢
  • 用任务管理器「结束任务」或断电后，浏览器内核的配置可能损坏，下次启动表现为窗口空白 20~30 秒。
  • 程序不会再因此清空你的数据。早期版本遇到异常退出会重建整个数据目录，那会把关注列表、译文、API Key 一起删掉——这个行为已经移除。
  • 如果窗口长时间空白打不开，用命令行运行 GitHub Hotboard.exe --reset：它会把浏览器配置改名备份（EBWebView.old-时间）后重建，不会删除，确认没用可以自己删掉那个备份目录。
① 数据不是「秒级实时」
  • Star 数本身变化很慢，大项目每分钟也就涨个位数，1~2 分钟刷新一次已经足够。
  • GitHub 接口自身有缓存，你看到的数据可能比网页版晚几十秒。
  • 排名升降是相对「上一次刷新」比较的，不是 GitHub 官方榜单。
② 未登录有调用次数限制
  • 搜索接口：10 次 / 分钟。程序每次刷新只用 1 次，正常使用碰不到上限。
  • 仓库详情接口：60 次 / 小时。「我的榜单」每个仓库占 1 次，所以它只在打开该页或手动刷新时更新。
  • 如果频繁手动刷新又加了很多关注项目，可能会短暂提示「配额用尽」，等一会儿就好。
  • 在「关于」页填入一个只读的 GitHub Token，可以把搜索配额提到 30 次/分钟。Token 只存在本机。
③ 你的数据存在哪里
  • 榜单缓存、曲线历史、我的榜单，全部存在本机，不会上传到任何服务器。
  • exe 版位置：%LOCALAPPDATA%\GitHubHot（可在文件管理器地址栏直接粘贴）。
  • 网页版位置：浏览器的本地存储里，和具体浏览器绑定。
  • 删除这个文件夹 = 清空所有本地数据，曲线和关注列表都会没。想保留就别删。
  • 数据是按「地址」隔离的：程序固定用 127.0.0.1:8765。万一这个端口被别的软件占用，程序会退回 8766 并在界面顶部显示黄色提示——那种情况下数据看起来是空的，关掉占用端口的程序再打开就回来了。
  • 换电脑、换浏览器、清理浏览器数据，都会导致曲线从零开始。
④ 端口被占用会导致「数据像丢了」
  • exe 版会在本机 127.0.0.1:8765 起一个只读服务来加载界面。
  • 如果 8765 被别的程序占用，会自动换到 8766、8767……此时浏览器的本地存储相当于换了个「地址」，看起来像数据被清空了。
  • 解决办法：关掉占用端口的程序，或关掉多余的本程序窗口，重新打开即可恢复。
  • 不要同时开多个窗口，第二个实例会换端口，两边数据不互通。
⑤ 杀毒软件可能误报
  • exe 是用 PyInstaller 打包的，这类「自解压 + 内嵌浏览器」的程序经常被启发式引擎误判。
  • 如果被拦截，把 GitHub Hotboard.exe 加入信任 / 白名单即可。
  • 不放心的话，直接用网页版 github-hot.html，功能完全一致。

其他几条

  • 系统要求：Windows 10 1803 及以上 / Windows 11。exe 依赖系统自带的 WebView2 运行时（装了 Edge 就有）。
  • 断网也能开：会显示上次缓存的榜单，并标注数据时间；恢复网络后自动补上。
  • 流量：每次刷新约 650 KB。在意流量就把间隔调成 5 分钟或「手动刷新」。
  • DeepSeek 插件榜首次加载要下 8.7 MB 的目录文件（几十秒）；之后直接读本地缓存，秒开，并在后台静默更新，不会卡界面。
  • 插件榜单只是索引，不代表安全审查。装第三方插件前请自行核对来源与权限，尤其是能读写文件、执行命令、操作浏览器的插件。
  • 本程序只读不写：不会修改你的任何文件，也不会往 GitHub 提交任何内容。

五、常见问题

打开后一直是「正在连接…」或空白？

先检查网络能否访问 api.github.com（公司网络或代理可能拦截）。如果是 exe 版，试试关掉重开；仍不行就用网页版打开 github-hot.html 看是否正常。

提示「接口配额用尽」？

GitHub 对未登录调用的限制。等几分钟会自动恢复，程序会在倒计时结束后重试。频繁手动刷新会更快耗尽配额。

曲线一直是空的？

至少需要 2 个采样点才画得出来。把刷新间隔改成 30 秒，等 1~2 分钟再点开任意一行就能看到。注意程序关掉期间不采样。

「我的榜单」添加后显示「未找到」？

仓库名要写成 owner/repo 的完整形式，区分大小写。私有仓库未登录时读不到。拼写错误也会显示未找到，删掉重新添加即可。

窗口打不开 / 白屏 / 一闪就退？

多半是上次异常退出（强制结束进程、断电）把浏览器内核的配置目录弄坏了。用命令行运行 GitHub Hotboard.exe --reset 即可：它会把配置目录改名备份后重建，不会删你的数据。还不行就用网页版。

如果界面顶部出现黄色提示条说「运行在 8766」，那是端口被占用导致的，不是配置坏了——关掉占用 8765 的程序再打开即可。

能改成只看我关心的那些项目吗？

可以。用记事本打开 github-hot.html，搜索 const CURATED，按 ['owner/repo','分类','一句话点评'] 的格式改，保存后刷新页面即可。分类名对应上面的 CATS。或者直接用「我的榜单」，不用改文件。

数据多久更新一次？

由右上角间隔决定，默认 2 分钟。窗口最小化时浏览器会节流定时器，切回来会自动补刷一次。

六、以后怎么更新

这个程序刻意做成了界面与外壳分离，所以大多数更新不需要重新打包。

情况 A：只改界面（绝大多数情况）

  1. 拿到新的 github-hot.html（发布包里默认不带这个文件，需要更新时才放）。
  2. 放到 exe 同目录即可；想更稳妥就放进 web\ 子文件夹（优先级更高）。
  3. 关掉程序重新打开，界面就是新的了。

加载优先级：web\github-hot.html → 同目录 github-hot.html → exe 内置版本（兜底）。所以放一个外部 HTML 就能覆盖界面，删掉就回到内置版。

改坏了怎么办？把外面那份 github-hot.html 删掉或改名，程序会自动回退到打包时内置的版本，一定能打开。

情况 B：改了 Python 侧（托盘、通知、窗口行为等）

这类改动必须重新打包。双击 打包.bat 即可：脚本会自动检查并安装依赖，约 40 秒后生成的新 exe 会直接覆盖同目录的旧 exe。前提是本机装有 Python 3.10 以上。

注意：重新打包时 github-hot.html 会被重新嵌入 exe。如果你之前改过它，记得保留修改，否则新 exe 的内置版本会回退到打包时的那份（不过外部文件仍然优先，所以影响不大）。

更新不会丢数据

榜单缓存、曲线历史、我的榜单都存在 %LOCALAPPDATA%\GitHubHot，与 exe、html 完全分离。替换程序、升级版本都不影响你已积累的数据。

七、便携模式与备份迁移

便携模式：数据跟着文件夹走

exe 同级有一个 portable.txt，只要它在，程序就把数据存到同目录的 data\ 里，而不是系统的用户目录。效果是：

  • 把整个文件夹拷到 U 盘或另一台电脑，双击 exe，关注列表、曲线、译文、设置全都在。
  • 换电脑不用重新配置，也不会出现"数据像丢了"的情况。
  • 删掉 portable.txt 就回到系统目录存储（数据不会自动搬回去）。
从旧版升级过来的？第一次以便携模式启动时，程序会自动把 %LOCALAPPDATA%\GitHubHot 里的旧数据复制到 data\，不需要手动操作。

备份与迁移：导出一个文件

「关于」页底部有「导出备份 / 从文件导入」。备份包含：我的榜单、Star 曲线历史、翻译记录、界面设置。

  • 导出会生成一个 hotboard-backup-2026-01-01.json，普通项目约十几 KB。
  • 导入会覆盖当前全部本地数据，操作前会弹确认框。
  • 如果浏览器没弹下载，展开「手动复制备份内容」，把文本框里的内容复制保存成 .json 即可。
  • 备份不含 GitHub Token 和翻译 Key，换设备后需要重新填写——这是刻意的，避免密钥跟着文件外流。

八、自己加功能怎么做

先判断属于哪一类，成本差别很大：

想加的东西改哪个文件要重新打包吗
新榜单、新列、新样式、新交互github-hot.html不用
换数据源、改接口、调刷新逻辑github-hot.html不用
托盘、开机自启、系统通知、窗口行为app.py要
要用新的第三方库build.py + app.py要

A 类：纯界面改动（最常见）

  1. 先复制一份 github-hot.html 做备份。
  2. 用编辑器打开（VS Code、Notepad++ 都行），保存时必须是 UTF-8，否则中文会乱码。
  3. 改完先双击这个 HTML，用浏览器打开验证——改坏了浏览器会直接告诉你哪一行报错。
  4. 确认没问题，关掉程序重新打开，exe 会自动加载改好的版本。
要看报错？用命令行运行 GitHub Hotboard.exe --debug，然后在窗口里右键 → 检查，就能打开开发者工具看控制台、查元素、改样式试效果。

文件里的结构大致是这样，按关键字搜索就能定位：

搜索这个它的作用
CATS / CURATED分类名称和精选清单，纯数据，改起来最安全
const S =全局状态（当前标签、排序、缓存等）
searchRepos / getRepo所有 GitHub 接口请求都从这里发
refresh / fillCategories刷新流程：先出首屏，再后台补全
renderTop / renderNew /
renderCat / renderDsh / renderMine		五个页面各自的渲染函数
histPush / pointsOf /
sparkSVG / bigChart		增长曲线的采样与绘制
switchView标签页切换
addEventListener按钮、快捷键、点击事件的绑定

B 类：需要 Python 侧的能力

比如「最小化到托盘后继续采样」「有新项目进榜时弹系统通知」「开机自启」。这类功能浏览器做不到，要改 app.py，改完双击 打包.bat 重新生成 exe。

C 类：要引入新的第三方库

先在 build.py 的 ensure() 里加一行（打包时会自动安装），再视情况补 --collect-all 参数把库的数据文件一起打进去。这一步最容易出问题，建议改之前先备份 build.py。

一条经验：改动前先备份，出问题就用备份覆盖回去。因为界面是外部文件优先，只要把 github-hot.html 删掉，程序就退回内置版本，永远不会彻底打不开。
